- Generated by Claude Code: `Core/Application` (ITenantContext, IComponentCatalog, CatalogComponent, IBuildRepository,
  BuildRequest + ComponentQuantity, ValidationErrors, ValidationResult<T>, BuildResolver, CompatibilityCheckService,
  SavedBuild, BuildService); `Core/Domain/Components/ComponentType`; `Infrastructure` (AppDbContext with query filters +

  package `Microsoft.EntityFrameworkCore.Sqlite` 10.0.15 (latest 10.x; 11.0.0 targets .NET 11).
- Key decisions proposed: `ComponentType` lives in Core, not in Infrastructure/Entities as STAGE2_PLAN §2 lists it,
  because the Core port `IComponentCatalog.ListAsync(type?)` needs it (dependencies point inward);
  `BuildRequest` fields are nullable so missing fields become 400 validation errors keyed by JSON field name
  ("cpuId", "ram.quantity", "storage[1].id"), all collected at once; wrong-type check uses the spec record type
  (`spec is CpuSpec`); "not found" message is identical for unknown and other-tenant IDs;
  `ValidationResult<T>` = value or errors; `BuildService.UpdateAsync` returns null for not found and checks it BEFORE
  validation (another tenant's ID is always 404, never 400); `SavedBuild` has no TenantId (the data layer owns it);
  Components key is (TenantId, Id) so IDs are unique per tenant; SavedBuilds.TenantId is also an EF concurrency token,
  so UPDATE/DELETE SQL includes "AND TenantId = @original" (third isolation layer on top of filter + guard);
  repositories use FirstOrDefaultAsync instead of DbSet.FindAsync (FindAsync can skip query filters for tracked
  entities); cooler JSON stores "kind": "Air"/"Aio"; JSON columns use camelCase + enum strings; seed builds are checked
  through the real resolver + engine, so `SeedData.InitializeAsync` takes the `CompatibilityEngine` from the caller;
  seeding is idempotent per tenant; `UpdatedAt` is `DateTimeOffset`, lists ordered by name.
